## Implemented, not proposed

- `src/lib/engine/state.ts`: one immutable application state, region selection, activation count, navigation progress and reduced preference. Shared by renderer, HTML controls and navigation.
- `scene.ts`: persistent original 3D composition of four thick parametric vaulted shells, different region joinery, concave chassis, amber core and physical continuous arterial band. Interface translucency, services folds, data lamellae and intelligence lens. PMREM room lighting, shadow, clearcoat and custom finite flight shader. Not Kia Bai code, water, assets or pool geometry; not the old M sculpture or terrain.
- `input.ts`: browser-owned wheel/touch/keyboard/anchors/history, converted to world progress without trapping input. Interaction model chosen as short pinned camera journey, not mandatory virtual-scroll imitation.
- `anchors.ts`: projected label layout with collision resolution. Displaced labels retain an anchor tether. Native 44px controls are the keyboard/touch alternative to raycast geometry.
- `EngineHero.svelte`: immediate Muhammed Munir / Full-Stack Engineer × AI; synchronized 3D-projected HTML labels, short eMesys reveal using both projected coordinates within responsive reading bounds, SSR SVG and independent semantic content. Reduced motion snaps to milestone poses. Root wrapper now uses this component. No other portfolio sections built.

Region activation starts a finite 2.6s shader signal from selected region, then sequential neighbor material/geometry/light responses, while selected region remains open. Raycasting operates on a completed tap (movement/time threshold), not initial scroll touch. Cursor hover affects region bend, not just camera. HTML and direct canvas selection use the same store. AI copy is a focus in tooling/experiments, not deployed AI inference. eMesys facts source system-projects.ts; illustrative structures are not production topology.
